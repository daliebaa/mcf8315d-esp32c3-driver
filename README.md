# 用 ESP32-C3 驱动 MCF8315D

> 一台 9V 小风机，一颗 TI 的无感 FOC 驱动芯片，和一周的反复折腾。
> 这个仓库把最后能稳定跑的那套配置和代码留了下来。

先说清楚它不是什么：**这不是一份"照着接就能用"的接线图**，而是一份调参记录。
MCF8315D 这颗芯片参数多到离谱（24 个影子寄存器、200 多个字段），手册只告诉你每个字段能填什么，
不告诉你填了会怎样。下面这些数值，全是在台架上一项一项试出来的。

如果你手上是**另一台电机**，那这里的数值对你几乎没用 —— 但"怎么试"的顺序应该有用，见[第 6 节](#6-换电机要改哪里)。

---

## 1. 硬件怎么接

控制侧只用了三根线：**SPEED / nFAULT / FG**。另外 SDA/SCL 用于配置。

| MCF8315D 引脚 | ESP32-C3 | 说明 |
|---|---|---|
| SDA | GPIO7 | 开漏，5.1k 上拉到 **AVDD** |
| SCL | GPIO8 | 同上。⚠ 这块板 GPIO8 还接着板载 LED，见第 7 节 |
| SPEED/WAKE | GPIO5 | 输出 5 kHz PWM，占空比 = 转速百分比 |
| nFAULT | GPIO10 | 开漏，下降沿中断 |
| FG | GPIO6 | 开漏，转速脉冲 |
| DRVOFF | 接地 | 不用软件控制 |
| BRAKE | GPIO4 | 低电平 = 不制动 |
| EXT_WD / EXT_CLK | 接地 | 不使用外部看门狗/时钟 |

供电上有三个容易搞错的地方，都是我自己踩过的：

- **AVDD（pin 17）是芯片内部 3.3V LDO 的输出，对外只有 20mA**。I2C 的四根上拉挂这里刚好（约 2.6mA），
  但别指望它带别的负载。
- **Buck 是电阻模式，外部负载必须 < 10mA**，只够点一个 LED。千万别拿它给 MCU 供电——ESP32 开 WiFi
  峰值 300mA 级，差几十倍。
- `BUCK_SEL` 选 3.3V 时 `BUCK_PS_DIS` **必须 = 1**。否则 AVDD 会改从 buck 的输出取电，
  buck 一抖动，你的 I2C 上拉就跟着抖，总线直接失联。

## 2. 跑起来

```bash
pio run                 # 编译
pio run -t upload       # 烧录（默认走 USB CDC）
pio device monitor      # 115200
```

依赖 PlatformIO + `espressif32` + Arduino framework，`platformio.ini` 里带了 `ARDUINO_USB_CDC_ON_BOOT=1`。

**一个坑**：ESP32-C3 用原生 USB 时，串口工具打开端口必须**拉高 DTR**，否则芯片认为"没人在听"，
一个字都不往外发。我第一次遇到时盯着空窗口查了半小时，以为是固件挂了。

串口能干什么：

| 命令 | 作用 |
|---|---|
| `0`–`100` | 设转速百分比（就是 SPEED 脚的 PWM 占空比），`0` 停机 |
| `p` | 状态（地址 / 转速 / 故障 / 错误计数） |
| `f` | 读并解码故障寄存器，调参时最常用的一条 |
| `c` | 清故障 |
| `d` | 打印影子寄存器 0x080–0x0AE |
| `s` | 重新扫描 I2C 地址 |
| `P` | 把参数表写进器件 EEPROM（还要再输一次 `W` 确认） |
| `r AAAA` / `k AAAA MASK VALUE` | 读寄存器 / 读-改-写寄存器（现场调参，不用重烧固件） |
| `h` | 帮助 |

`k` 这条是救命的：改一个参数重烧一次固件要 15 秒，用它改是 1 秒。

## 3. 调参时踩过的坑

这一节是整个仓库最值钱的部分。手册上查不到，只能试出来。

### 坑 1：转速读数差了整整 3 倍

`FG_DIV` 的复位值是 `0h`，含义是"每电周期输出 3 个脉冲"。
我按"每机械转 7 个脉冲"（7 对极）去算转速，结果读出来永远对不上，最后发现差了 3 倍。

改成 `1h`（每电周期 1 个脉冲）之后，7 对极就是每机械转 7 个脉冲，`FG_PULSES_PER_REV = 7.0f`，对上了。

**教训**：器件复位值不是"合理的默认值"，是"最省事的值"。换新片不显式配置，读数就是错的。

### 坑 2：给个 20% 转速，转十几秒就停

故障码是 `HW_LOCK_LIMIT`——硬件比较器在 3.75A 处跳闸。可我的电流限值明明设的是 2.812A。

原因是**电流纹波**：这颗电机电感极低（MPET 测出来落在表的"自测档"，比表里最小的 6µH 还小），
载波频率低的时候纹波峰峰值能到好几个安培，叠加在平均电流上就顶穿了比较器阈值。

实测扫了一遍载波频率：

| 载波 | 结果 |
|---|---|
| 10 ~ 45 kHz | 转十几秒报 `HW_LOCK_LIMIT` 停机 |
| 50 / 55 / 60 kHz | 正常 |

**50 kHz 是这颗电机的硬下限**，不是"建议值"。手册 §6.3.17 只写了"L/R 越低的电机越需要高开关频率"，
没告诉你越界之后是这个现象。

顺带一个反直觉的结论：开环电流也不能往上加。试过 3.125A，平均电流离 3.75A 只剩 0.6A，
纹波一顶就跳闸，反而更糟。

### 坑 3：60 kHz 有一阵阵刺耳的声音

把载波固定在 60 kHz 之后，噪音里有一阵阵"吱"的声音，断续的，不是稳态单音。

试了 PWM 抖动（spread spectrum，手册 §6.3.18）：把开关频率在设定值附近持续摆动，
把集中在单一频点的能量摊成一段频带。最后这组最舒服：

```
载波 55 kHz + 抖动 ±5% + 三角波模式
```

听感从"尖锐单音"变成"轻微沙沙声"。注意抖动深度是相对于载波的，
55 kHz ±5% = 52.25~57.75 kHz，还在安全区；要是把载波设回 50 kHz 还开 ±10%，就会掉到 45 kHz，
正好撞进坑 2 的禁区。

### 坑 4：降速再给速度，电机会"顿一下"

场景：跑在 20%，给 `0`，0.3 秒后再给 40%。转速表是这样的：

```
609 → 17 → 394 → 249 → 51 RPM     ← 抽动
```

原因是给 `0` 之后电机靠惯性滑行（这颗芯片开了 AVS，减速不制动、不回灌母线），
几秒都停不下来。这时候再给速度，器件会**重新走一遍完整启动流程**（判定位置 → 对齐 → 开环加速），
对着一个还在转的转子做这件事，位置大概率判错，于是猛拽一下。

解法是把两个开关打开：

- `ISD_EN = 1`：启动前先用三相电压测出转速 / 角度 / 方向
- `RESYNC_EN = 1`：如果转子还在同方向转，直接用测出来的状态接上闭环，不重走启动流程

同一场景再看：

```
240 → 660 → 1440 → 2057 RPM       ← 连续上升
```

### 坑 5：偶尔启动失败

大概 2~3 次里会有 1 次起不来，故障码是 `ABN_BEMF` + `MTR_LCK`——开环阶段转子没跟上。

试了一圈参数，最后有效的组合是：

| 参数 | 值 | 为什么 |
|---|---|---|
| `ALIGN_OR_SLOW_CURRENT_ILIMIT` | 2.187 A | 对齐电流不够，转子没被真正拉到对齐位置，开环一起步就打滑 |
| `ALIGN_TIME` | 1 s | 复位值只有 10 ms，**电流还没爬到设定值就跑完了** |
| `OL_ACC_A1` | 250 Hz/s | 反直觉：开环加速要**快**。低速区观测器最弱，快速穿过去比慢慢爬稳 |
| `OL_ILIMIT` | 2.812 A | 再高就撞坑 2 的 3.75A 比较器 |

改完之后连续 8 次冷启动全部成功。剩下那点概率没法完全消掉——无感驱动在低速段本来就靠猜，
固件里加了**启动失败自动重试**（停机 → 等转子滑停 → 清故障 → 重新给速度，最多 3 次），
只对启动类故障重试，过压过温一律不重试。

### 坑 6：这台电机用 MPET 测出来的参数是错的

MCF8315D 有个很好用的功能叫 MPET，能自动测电机参数。但它在这台电机上把反电动势常数
`Ke` 测成了 `0x02`（0.7 mV/Hz），只有真实值的一半——因为电感太小，测量脉冲的响应还没稳定就采样了。

结果就是速度环把转速估低，给 20% 会一路加速到 46% 才失步。

所以配置文件里的 `MOTOR_BEMF_CONST = 0x0A`（1.5 mV/Hz）是**人工标定值**，不是 MPET 的结果。
换电机时这一项务必自己验一遍。

## 4. 配置表长什么样

`config_opt.h` 里有一张 65 项的表，每项是 `{地址, 位掩码, 目标值, 说明}`：

```c
{ 0x088, 0x00000F00UL, ((uint32_t)CFG_FG_DIV) << 8, "FG_DIV（1h = 每电周期 1 脉冲 → 7 脉冲/转）" },
```

写入用的是**读-改-写**：只动掩码圈住的那几位，`bit31` 的 PARITY 和其它字段原样保留。
这一点很重要——整值写会把 PARITY 冲掉，之后器件做 EEPROM 校验就会报错。

| 寄存器 | 项数 | 内容 |
|---|---|---|
| 0x080 ISD_CONFIG | 4 | 初始速度检测 + 重同步 |
| 0x084 MOTOR_STARTUP1 | 5 | 对齐方式 / 电流 / 时间 / 斜率 |
| 0x086 MOTOR_STARTUP2 | 4 | 开环电流 / 加速度 / 换相阈值 |
| 0x088 CLOSED_LOOP1 | 8 | 载波 / 抖动 / 加减速 / AVS / FG |
| 0x08A CLOSED_LOOP2 | 6 | 停机方式 / 电机 R、L |
| 0x08C + 0x08E | 5 | Ke、速度环 Kp/Ki、MAX_SPEED |
| 0x090 FAULT_CONFIG1 | 5 | 各阶段电流限值、EEP_FAULT_MODE |
| 0x092 FAULT_CONFIG2 | 13 | 三种堵转检测 + 母线欠压/过压保护 |
| 0x0A0 INT_ALGO_1 | 3 | ISD 时间常数、SPEED 脚滤波 |
| 0x0A4 / A6 / A8 / AA / AC / AE | 12 | 引脚 / 器件 / Buck / 方向 / 过压 |

为什么非要配满 65 项？因为**复位值基本全是 0，而"0"不等于"能用"**：

- `FG_DIV` = 0 → 转速读数差 3 倍（坑 1）
- `ALIGN_TIME` = 0 → 对齐只有 10 ms（坑 5）
- `LOCK1/2/3_EN` = 0 → 三种堵转检测**全关**，电机真卡住时没有任何保护
- `MIN_VM_MOTOR` / `MAX_VM_MOTOR` = 0 → 母线电压无限制

固件每次上电都会把这张表重新下发一遍。所以**芯片是全新的、EEPROM 是空的，接上 MCU 照样能跑**——
EEPROM 只是为了让"不接 MCU 单独上电"时也能工作。

逐字段的含义（每一个 bit 是什么、为什么填这个值）在 **[docs/config_reference.md](docs/config_reference.md)**。

## 5. 换芯片 / 重新焊接之后

参数存在两个地方：

1. **MCU 固件里** —— 每次上电自动下发给器件
2. **器件 EEPROM 里** —— 执行 `P` 命令写入

热风枪把芯片吹下来重焊、或者换新片之后：

```
上电 → 串口输入 P → 再输入 W 确认 → 断电重启
```

高温可能会影响 EEPROM 里的内容，所以重焊后建议重走一遍。

> 仓库里 `release/` 目录有一份**产线烧录固件**：接一片烧一片，烧完自动提示换片，
> 同一片不会被重复写（省 EEPROM 的 2 万次寿命）。把 `EN_PROVISION_MODE` 改成 1 也能自己编出来。

## 6. 换电机要改哪里

按这个顺序来，前一步不稳就别急着下一步：

1. **`MOTOR_RES` / `MOTOR_IND` / `MOTOR_BEMF_CONST`** —— 相电阻、电感、反电动势常数。
   MPET 能测前两个，`Ke` 建议人工标定（见坑 6）。
2. **`MAX_SPEED`** —— 电频率 = RPM ÷ 60 × 极对数。PWM 占空比 100% 就对应这个转速。
3. **`FG_DIV` + `FG_PULSES_PER_REV`** —— 两者必须自洽，否则转速显示是错的。
4. **电流四件套** —— `ILIMIT` / `OL_ILIMIT` / `ALIGN_ILIMIT` / `LOCK_ILIMIT`，按电机和供电能力定。
5. **`PWM_FREQ_OUT`** —— 电感越低越要高。从 20~25 kHz 起往上试，症状见坑 2。
6. **启动三段** —— `ALIGN_ILIMIT` → `OL_ACC_A1` → `OPN_CL_HANDOFF_THR`。
   调的时候盯着 `f` 的输出：报 `ABN_BEMF`/`MTR_LCK` 就加对齐电流或加快开环；
   报 `HW_LOCK_LIMIT` 就降电流或提载波。
7. **`FAULT_CONFIG2`** 的堵转阈值按实际负载微调，别让正常负载被判成堵转。

## 7. 几个必须知道的坑（硬件）

- **GPIO8 是板载 LED 引脚**。这块板的 SCL 也接在 GPIO8 上，LED 那条 5.1k 通路会额外把 SCL 上拉。
  电气上无害，但你不能再把 GPIO8 当灯用，更不能让它输出低电平——那等于把 I2C 时钟拉死。
- **GPIO9 是 BOOT 按键，同时是 strapping 脚**。别把 BRAKE 接上去：上电瞬间它会被拉高，
  而 BRAKE 高电平 = 制动，电机会被一直摁住。
- **Sleep 会关掉 AVDD**。SPEED 引脚静默超过 `SLEEP_ENTRY_TIME`（本工程 200ms）器件就休眠，
  AVDD 一关，I2C 上拉全失效。所以固件停机时仍然输出 1% 占空比保活——
  此时 `DUTY_CMD` 仍是 0，电机不转。
- **散热**。TSSOP-24（PWP）在 2.8A 连续电流下全靠底部散热焊盘往铜箔导热。
  调试板上焊接不实时，跑十几分钟就很烫。正式板一定要铺铜 + 打过孔，否则长期可靠性没保障。
- 器件峰值相电流额定 **3.5A**（PWP 封装），而 `ILIMIT` 的 4 位档位最高只能到 3.75A——已经超额定了，
  别把它当正常工况用。
